# 开发指南

## 审查-修复工作流

1. 主 Agent 审查 → 写入 `docs/code-review.md`（唯一审查文档）
2. 执行 Agent 按 code-review.md 修复 → 每项修复对应一个 git commit
3. 执行 Agent 交付：修改文件清单 + commit hash + 测试运行结果
4. 主 Agent 复审：读 diff + 跑测试 + 手动验收核心功能
5. 通过则关闭该轮，不通过则回到第2步

### 沟通文件

- `docs/code-review.md` — 当前轮审查意见（唯一，已完成任务移到 archive/）
- `docs/status.md` — 当前项目状态（唯一）
- `docs/archive/` — 历史轮次产物（只读，不再修改）

### 硬性要求

- 每次代码修改后必须运行现有测试套件
- 审查编号不写入代码注释，用 git commit message 追踪
- 交付必须包含测试运行结果，不允许只说"已修复"
- 写 Python 文件用 Write 工具或 Python 脚本，禁止用 PowerShell Set-Content（会写入 BOM 导致 ast.parse 失败）

## 手动验收 Checklist

每次代码修改后，按以下清单验收。「每次必验」项每次都要走，「发布前」项在打包发布前走。

| 类别 | 检查项 | 怎么验 | 频率 |
|---|---|---|---|
| 正常路径 | 准星显示/隐藏 | 按热键，屏幕上准星出现/消失 | 每次必验 |
| 正常路径 | 切载具 | 切换载具后准星图片对应变化 | 每次必验 |
| 正常路径 | 切弹种 | 切换弹种后准星图片对应变化 | 每次必验 |
| 正常路径 | 切倍率 | 循环切换倍率，准星图片对应变化 | 每次必验 |
| 边界路径 | 快速连续操作 | 连按10次倍率切换，无卡顿无状态错乱 | 每次必验 |
| 边界路径 | 异常配置 | config.json 改坏（删括号），启动后自动恢复默认 | 发布前 |
| 边界路径 | 资源缺失 | 某个准星图片改名，启动不崩溃，准星区域空白 | 发布前 |
| 关闭路径 | 正常关闭 | 点关闭，任务管理器确认进程退出，无残留 | 每次必验 |
| 关闭路径 | 强制关闭 | 任务管理器杀进程，再启动配置不损坏 | 发布前 |
| 回归 | 本次修改涉及功能 | 专门验这次改的功能的正常+边界路径 | 每次必验 |

## 鼠标输入机制

GS 项目存在两套鼠标输入机制，用途完全不同，**不是重复造轮子**。

### MouseHook（低级鼠标钩子）

- **文件**：`core/mouse_hook.py`
- **API**：Windows 低级钩子 `WH_MOUSE_LL`
- **用途**：热键捕获——知道"哪个鼠标按键被按下/释放"
- **限制**：鼠标移动数据被 Windows 加速处理过，不适合精确测量

### RawInputReader（原始输入）

- **文件**：`core/angle_meter.py`
- **API**：Windows Raw Input API（`WM_INPUT` + `RAWINPUT`）
- **用途**：角度仪精确测量——获得硬件级原始鼠标增量
- **限制**：需要 `WA_NativeWindow`，必须在 nativeEvent 中处理

### 为什么需要两套？

| 需求 | MouseHook | RawInput |
|---|---|---|
| 捕获鼠标按键作为热键 | ✅ | ❌ |
| 精确测量鼠标移动距离 | ❌ | ✅ |
| 角度仪校准/使用 | ❌ | ✅ |
| 热键绑定（鼠标键） | ✅ | ❌ |

两套机制共享 `core/win32_utils.py` 的统一 DLL 入口。
