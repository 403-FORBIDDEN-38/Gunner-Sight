# 任务规格书：GunnerSight 需求规格说明书

## 1. 背景与目标

### 项目背景
GunnerSight 是一款已开发至 V0.014 的实战型游戏辅助软件，以屏幕叠加层（Overlay）为核心，集成准星显示、载具/弹种/倍率切换、热键管理、信息数显、建队宏、角度仪、资源库等功能。当前处于"修细节 + 统一架构 + 准备发布"的收尾阶段。

### 文档目标
本需求规格说明书不是从零设计，而是对已有项目的**系统化文档化**，用于：
- 统一团队对系统行为和边界的认知
- 为发布准备提供功能清单和验收依据
- 为后续开发和重构提供需求基线
- 让新成员快速理解系统全貌

### 目标读者
项目开发者、测试人员、发布负责人。

## 2. 本质需求（VDR 反推产出）

### 不可变核心约束
1. **叠加层约束**：Overlay 必须透明、可点击穿透（不影响下层窗口操作）、始终在最顶层（不被全屏游戏覆盖）。
2. **热键约束**：所有热键必须全局生效，不与游戏内按键冲突，支持自定义和持久化。
3. **状态一致性约束**：各功能模块必须通过统一状态机协调，禁用/启用状态必须全局一致，不能出现一个模块认为已禁用另一个仍在执行的情况。
4. **配置持久化约束**：所有用户配置必须通过唯一配置文件（config.json）持久化，重启后恢复，不允许散落多处配置。
5. **性能约束**：Overlay 渲染和热键响应必须低延迟（<50ms 感知延迟），CPU/内存占用不得影响游戏正常运行。
6. **可扩展性约束**：新增准星样式、新增功能模块不得修改核心架构，通过资源文件和模块接口扩展。

### 可变实现选择
- 编程语言（Python）、GUI 框架（PyQt/PySide）、打包方式（PyInstaller）属于实现选择，不写入本质需求。
- 具体的准星图片资源、UI 布局细节属于实现选择。
- 角度仪的具体算法实现属于实现选择，但其行为约束（精度、响应速度）属于需求。

## 4. 非功能需求

### 性能
- Overlay 渲染延迟 < 50ms（用户操作到画面更新的感知延迟）
- 热键响应延迟 < 100ms（按键到功能执行）
- 空闲状态 CPU 占用 < 5%，内存占用 < 200MB
- 游戏运行时不得造成可感知的帧率下降

### 兼容性
- 操作系统：Windows 10 / Windows 11（64位）
- 分辨率：支持 1080p / 2K / 4K，Overlay 位置按比例适配
- 显示模式：支持窗口化、无边框窗口、全屏（Overlay 必须在全屏游戏上可见）
- 多显示器：支持在指定显示器上显示 Overlay

### 安全性
- 不读取、不修改游戏内存
- 不注入游戏进程
- 不包含任何恶意代码
- 配置文件仅保存在本地，不上传任何数据
- 热键钩子（mouse_hook）仅用于全局热键，不记录用户按键内容

### 可靠性
- 异常情况下不得崩溃导致游戏被打断（Overlay 崩溃可恢复，不影响主程序）
- 配置文件损坏时能自动恢复默认配置，不得无法启动
- 热键注册失败时应有明确提示，不得静默失败

### 可维护性
- 核心模块（config_manager、hotkey_manager、state_machine、overlay）接口稳定
- 新增功能模块通过统一接口接入，不修改核心模块
- AGENTS.md 中记录的"最小改动基于病灶根源"规范必须遵守

## 7. 执行 Agent 工作约束

1. **必须参考源码**：撰写前必须读取 GunnerSight 源码目录结构和全部 core/ 模块文件，确保功能清单准确。源码路径由用户提供。
2. **不编造功能**：源码中没有的功能不得写入需求规格。命名不透明的模块（如 xcj.py）必须读源码确认功能后再写；无法确认的标注为"待确认"并写入 change-request.md，不得猜测。
3. **不修改本规格书**：对 task-spec.md 有疑问时写入 change-request.md，不自行修改。
4. **配置文件参考**：第 5 章数据与配置必须参考实际 config.json，不得编造字段。
5. **AGENTS.md 规范参考**：项目根目录下 AGENTS.md 记录了性能三问审查法、病灶根源优先、墓碑代码清理、AI 易见错误清单等规范，撰写非功能需求和边界异常时必须参考，确保文档与项目实际开发规范一致。
6. **简洁性**：遵循 ponytail 原则，不用 20 个词解释 1 个词能说清的东西。功能描述精确到行为，不写废话。
7. **可验证性**：每个功能点的描述必须可测试，验收标准必须可执行。
