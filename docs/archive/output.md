## 第 1 章：引言

### 1.1 编写目的

本文档对 GunnerSight（屏幕准星辅助软件）已有功能进行系统化文档化，用于统一团队对系统行为和边界的认知，为发布准备提供功能清单和验收依据，为后续开发和重构提供需求基线。

### 1.2 项目背景

GunnerSight 是一款实战型游戏辅助软件，以屏幕叠加层（Overlay）为核心，集成准星显示、载具/弹种/倍率三级切换、全局热键管理、信息数显（测距仪）、建队宏、角度仪、资源库等功能。当前处于"修细节 + 统一架构 + 准备发布"的收尾阶段。

软件基于 Windows 平台，使用 Python + PyQt5 开发，通过 Win32 API 实现窗口置顶、点击穿透和全局钩子，不读取、不修改游戏内存，不注入游戏进程。

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| Overlay | 屏幕叠加层，透明、置顶、点击穿透的窗口，用于绘制准星和数据 |
| 载具（Vehicle） | 游戏中的载具单位，每个载具有独立的弹种和倍率配置 |
| 弹种（Ammo Type） | 载具的弹药类型，不同弹种对应不同准星图片 |
| 倍率（Magnification） | 准星的缩放档位，每个弹种可绑定多个倍率及对应准星图片 |
| 信息数显（XCJ/Rangefinder） | 通过屏幕截图和图像识别在 Overlay 上显示距离等数据的功能 |
| 角度仪（Angle Meter） | 通过 Raw Input 读取鼠标增量，实时计算并显示炮塔俯仰角的模块 |
| 建队宏（Squad Macro） | 自动化按键序列，用于在游戏中一键建立小队 |
| 状态机（State Machine） | 统一管理当前载具、弹种、倍率、Overlay 可见性等运行状态的模块 |
| 热键（Hotkey） | 全局生效的键盘或鼠标按键绑定，支持按下/松开触发 |
| 点击穿透（Click Through） | 窗口不接收鼠标事件，鼠标操作直接传递给下层窗口 |
| Raw Input | Windows 提供的硬件级输入读取接口，可获取鼠标增量而非光标位置 |
| 配置文件（config.json） | 唯一的用户配置持久化文件，包含所有设置和数据 |

## 第 2 章：系统概述

### 2.1 系统目标与定位

GunnerSight 定位为**游戏高烈度对抗场景下的辅助工具**，核心目标：
1. 在屏幕上叠加可自定义的准星图片，辅助瞄准
2. 通过载具/弹种/倍率三级切换，快速适配不同战斗场景
3. 提供信息数显、角度仪、建队宏等实战辅助功能
4. 全程低延迟、低资源占用，不影响游戏正常运行

**非目标**：不提供自动瞄准、自动射击、内存读取、进程注入等作弊功能。

### 2.4 用户角色与使用场景

**唯一用户角色**：游戏玩家（Squad 等游戏的载具炮手/车长）

**典型使用场景**：
1. 启动软件 → 选择载具 → 切换弹种/倍率 → 准星自动更新 → 进入游戏作战
2. 战斗中通过全局热键快速切换弹种/倍率，无需切出游戏
3. 使用信息数显功能获取目标距离数据
4. 使用角度仪实时掌握炮塔俯仰角
5. 开局时使用建队宏一键建立小队

## 第 3 章：功能需求

### 3.1 Overlay 核心模块

#### FR-001：Overlay 窗口创建与显示

- **功能描述**：创建全屏透明窗口，始终置顶，鼠标点击穿透，不获取焦点，不在任务栏显示。
- **输入**：程序启动
- **输出**：屏幕上出现透明 Overlay 窗口，覆盖整个主显示器
- **状态变化**：Overlay 从无到有，默认可见
- **正常流程**：程序启动 → 创建 QWidget → 设置无边框/置顶/工具窗口标志 → 设置透明背景 → 调用 Win32 API 应用点击穿透 → 显示窗口
- **异常流程**：Win32 API 调用失败时打印错误日志，窗口仍显示但可能不具备点击穿透
- **优先级**：P0

#### FR-002：准星图片绘制

- **功能描述**：在 Overlay 窗口中心绘制当前载具/弹种/倍率对应的准星图片。
- **输入**：准星图片文件路径（由状态机提供）
- **输出**：屏幕中心显示准星图片
- **状态变化**：切换载具/弹种/倍率时准星图片更新
- **正常流程**：状态机变化 → Overlay 接收新图片路径 → 从缓存或磁盘加载 QPixmap → 按缩放比例绘制到窗口中心
- **异常流程**：图片文件不存在时打印 `[Overlay] 准星图片不存在` 日志，Overlay 保持空白
- **优先级**：P0

#### FR-003：准星缩放与位置调整

- **功能描述**：支持全局缩放比例（默认100%）和XY偏移量调整，实时生效。
- **输入**：缩放百分比（0-200%）、偏移X（像素）、偏移Y（像素）
- **输出**：准星按比例缩放并偏移到指定位置
- **状态变化**：修改参数后 Overlay 立即重绘
- **正常流程**：用户在全局设置页调整滑块/输入框 → 配置保存 → Overlay 接收参数变化 → 使用缩放缓存重绘
- **异常流程**：缩放值超出范围时被控件限制，不产生异常
- **优先级**：P0

#### FR-004：准星反色切换

- **功能描述**：一键切换准星图片颜色反相，适用于不同背景对比度需求。
- **输入**：反色开关/热键
- **输出**：准星图片颜色反相显示
- **状态变化**：反色标志在 true/false 间切换
- **正常流程**：触发反色热键 → 状态机切换反色标志 → Overlay 使用反色缓存的 pixmap 重绘
- **异常流程**：无
- **优先级**：P1

#### FR-005：Overlay 显示/隐藏切换

- **功能描述**：通过热键或主窗口按钮切换 Overlay 可见性，默认每次启动时准星可见。
- **输入**：显示/隐藏热键（默认 F1）或主窗口按钮
- **输出**：Overlay 显示或隐藏
- **状态变化**：`overlay_visible` 在 true/false 间切换，主窗口按钮状态同步
- **正常流程**：触发热键 → 状态机切换可见性 → Overlay 调用 show()/hide() → 主窗口按钮文字更新
- **异常流程**：无
- **优先级**：P0

#### FR-006：图片缓存机制

- **功能描述**：对已加载的准星图片和缩放后的 pixmap 进行内存缓存，避免重复磁盘 IO 和缩放计算。
- **输入**：图片路径、缩放比例、是否反色
- **输出**：缓存命中时直接使用缓存 pixmap
- **状态变化**：缓存随图片切换增长，无上限清理（准星图片数量有限，36个）
- **正常流程**：请求绘制 → 检查 (path, scale, inverted) 缓存 → 命中则直接使用 → 未命中则加载/缩放后存入缓存
- **异常流程**：无
- **优先级**：P1（性能优化）

### 3.2 配置管理模块

#### FR-007：统一配置文件加载

- **功能描述**：程序启动时从 config.json 加载全部配置，文件不存在或损坏时使用最小骨架配置回退。
- **输入**：config.json 文件
- **输出**：内存中的配置数据结构
- **状态变化**：配置从磁盘加载到内存
- **正常流程**：启动 → 检查 config.json 存在 → 解析 JSON → 填充配置数据 → 执行数据迁移
- **异常流程**：文件损坏（JSON解析失败）→ 使用最小骨架配置（version/global_settings/hotkeys/vehicles/tags）→ 不覆盖用户文件
- **优先级**：P0

#### FR-008：配置自动保存（防抖）

- **功能描述**：任何配置修改后自动保存到 config.json，采用 500ms 防抖机制，避免频繁写盘。
- **输入**：配置数据变化
- **输出**：config.json 文件更新
- **状态变化**：内存配置 → 磁盘配置
- **正常流程**：set_* 方法被调用 → 请求保存 → 启动/重置 500ms 定时器 → 定时器到期 → 加锁写入 JSON
- **异常流程**：写入失败时打印错误日志，不崩溃
- **优先级**：P0

#### FR-009：载具配置管理

- **功能描述**：管理载具列表，每个载具包含名称、标签、弹种列表、倍率列表、各倍率绑定的准星图片。
- **输入**：载具名称、标签、弹种、倍率、准星图片绑定
- **输出**：配置中载具数据更新
- **状态变化**：载具增删改后配置更新
- **正常流程**：用户在载具配置页操作 → 调用 ConfigManager 对应方法 → 内存更新 → 触发防抖保存
- **异常流程**：删除当前载具时自动切换到第一个可用载具
- **优先级**：P0

#### FR-010：热键配置管理

- **功能描述**：管理全局热键和弹种热键配置，每个热键支持双键（key1/key2）和触发方式（keydown/keyup）。
- **输入**：热键动作、按键、触发方式
- **输出**：配置中热键数据更新
- **状态变化**：热键绑定修改后 HotkeyManager 重新加载
- **正常流程**：用户在热键设置页绑定按键 → 保存到配置 → HotkeyManager.reload_hotkeys() 重新注册
- **异常流程**：热键冲突时后注册的覆盖先注册的（当前实现，无冲突提示）
- **优先级**：P0

#### FR-011：角度仪配置管理

- **功能描述**：管理角度仪配置列表，每个配置包含名称、最低角/最高角范围、校准数据、关联载具、归零开关、归零热键。
- **输入**：配置名称、角度范围、校准数据、关联载具、归零设置
- **输出**：配置中角度仪数据更新
- **状态变化**：配置增删改后角度仪模块更新
- **正常流程**：用户在角度仪页操作 → 保存到配置 → 角度仪 Tab 加载当前配置
- **异常流程**：无
- **优先级**：P1

#### FR-012：测距仪配置管理

- **功能描述**：管理测距仪配置列表，每个配置包含截取区域1/2、结果显示区域、关联载具。
- **输入**：配置名称、区域坐标、显示设置、关联载具
- **输出**：配置中测距仪数据更新
- **状态变化**：配置增删改后测距仪模块更新
- **正常流程**：用户在信息数显页操作 → 保存到配置
- **异常流程**：无
- **优先级**：P1

#### FR-013：建队宏配置管理

- **功能描述**：管理建队宏配置，包括小队名称、是否锁队、循环间隔、热键绑定、关联载具。
- **输入**：小队名称、锁队开关、间隔ms、热键
- **输出**：配置中建队宏数据更新
- **状态变化**：配置修改后建队宏模块更新
- **正常流程**：用户在建队宏页操作 → 保存到配置
- **异常流程**：无
- **优先级**：P1

#### FR-014：配置数据迁移

- **功能描述**：旧版本配置在新版本加载时自动迁移字段格式，确保向后兼容。
- **输入**：旧格式 config.json
- **输出**：迁移后的内存配置（不自动写回，下次保存时更新）
- **状态变化**：旧字段格式 → 新字段格式
- **正常流程**：加载配置后 → 检测旧版倍率准星绝对路径 → 迁移为文件名 → 检测旧版弹种热键单键格式 → 迁移为双键格式
- **异常流程**：迁移失败时保留原值，打印日志
- **优先级**：P1

### 3.3 热键管理模块

#### FR-015：全局键盘热键

- **功能描述**：注册全局键盘热键，支持功能键（F1-F12）、字母、数字、修饰键组合，按下或松开时触发对应动作。
- **输入**：按键按下/松开事件（全局钩子）
- **输出**：对应功能动作信号
- **状态变化**：无
- **正常流程**：用户按下热键 → 全局键盘钩子捕获 → 查找注册的回调 → 边沿检测（避免长按重复触发）→ 发射信号
- **异常流程**：热键注册失败时打印日志
- **优先级**：P0

#### FR-016：全局鼠标热键

- **功能描述**：注册全局鼠标按键热键（左/中/右键、侧键），通过共享低级鼠标钩子实现。
- **输入**：鼠标按键按下/松开事件
- **输出**：对应功能动作信号
- **状态变化**：无
- **正常流程**：鼠标按键事件 → MouseHook 分发 → HotkeyManager 查找回调 → 边沿检测 → 发射信号
- **异常流程**：钩子过程中仅做事件入队，不执行耗时操作，避免系统鼠标卡死
- **优先级**：P0

#### FR-017：双键热键绑定

#### FR-048：共享低级鼠标钩子

- **功能描述**：MouseHook 提供全局共享的 WH_MOUSE_LL 低级鼠标钩子，HotkeyManager（全局热键）和 HotkeyLineEdit（热键绑定捕获）共用同一钩子实例，通过引用计数（acquire/release）管理生命周期，避免各自创建独立钩子导致系统钩子链过长。
- **输入**：鼠标按键按下/松开事件（系统级）
- **输出**：mouse_down / mouse_up 信号（分发给所有订阅者）
- **状态变化**：引用计数增减，最后一个持有者释放时停止钩子
- **正常流程**：第一个使用者调用 acquire() → SetWindowsHookExW 注册钩子 → 鼠标事件到达 → 钩子过程仅做事件入队（不执行耗时操作）→ 分发信号 → 最后一个使用者调用 release() → UnhookWindowsHookEx 卸载钩子
- **异常流程**：钩子注册失败时打印日志；钩子过程严格限制执行时间，避免系统鼠标卡死
- **优先级**：P0

#### FR-049：Win32 窗口样式工具

- **功能描述**：win32_utils 封装窗口扩展样式的 Win32 API 调用，提供 apply_click_through（设置点击穿透+工具窗口+不激活）和 set_click_through（启用/禁用点击穿透，保留工具窗口样式）两个函数，供所有 Overlay 窗口统一调用。
- **输入**：窗口句柄（hwnd）、是否启用点击穿透
- **输出**：窗口扩展样式（GWL_EXSTYLE）被修改
- **状态变化**：窗口样式变化
- **正常流程**：Overlay 窗口创建后 → apply_click_through(hwnd) → 设置 WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE；编辑模式时 → set_click_through(hwnd, False) → 清除 WS_EX_TRANSPARENT
- **异常流程**：hwnd 为空时直接返回不执行
- **优先级**：P0

```
│   ├── enabled: false

└── squad_macro
    ├── enabled: false
    ├── squad_name: ""
    ├── locked: true
    ├── interval_ms: 100
    └── hotkey: {key, trigger}
```

### 5.2 配置加载/保存流程

**加载流程**：
1. 程序启动 → ConfigManager 初始化 → 确定配置目录（开发环境：项目根目录；打包后：exe同级目录，回退 _internal）
2. 检查 config.json 存在 → 存在则解析 JSON → 不存在则使用最小骨架
3. 执行数据迁移（旧版绝对路径→文件名、旧版单键热键→双键）
4. 内存配置就绪

**保存流程**：
1. 任何 set_* 方法修改内存配置 → 调用 request_save()
2. request_save() 重置 500ms 防抖定时器
3. 定时器到期 → 获取保存锁 → 序列化为 JSON → 写入 config.json
4. 写入完成 → 释放锁

### 5.3 配置迁移与兼容性

| 迁移项 | 旧格式 | 新格式 | 触发时机 |
|---|---|---|---|
| 倍率准星路径 | 绝对路径（C:\...\resources\XXX.png） | 仅文件名（XXX.png） | 加载配置时 |
| 弹种热键 | {key, trigger} 单键 | {key1, trigger1, key2, trigger2} 双键 | 加载配置时 |

迁移仅修改内存，不自动写回磁盘；下次用户修改配置触发保存时，新格式写入磁盘。

### 5.4 资源文件结构

```
resources/
├── 载具名 弹种名 倍率X.png    # 命名规范：载具_弹种_倍率
├── ADF M2 1X.png
├── ADF M2 5X.png
├── ADF M2 12X.png
├── L11A1 1X.png
├── ...
└── 共36个图片文件（PNG格式为主）
```

- 格式：PNG（推荐，支持透明）、JPG、JPEG、BMP、GIF、WEBP
- 存储：开发环境在项目根 resources/；发布版在 exe 同级 resources/
- 引用：配置中仅存储文件名，运行时由 ResourceManager 解析完整路径

## 第 7 章：边界与异常

### 7.1 配置文件损坏

- **场景**：config.json 被外部修改导致 JSON 解析失败
- **系统行为**：捕获 JSONDecodeError → 使用最小骨架配置（version/global_settings/hotkeys/vehicles/tags）→ 打印日志 → 不覆盖用户损坏的文件 → 程序正常启动
- **用户感知**：配置恢复默认，载具/热键需要重新设置

### 7.2 热键注册冲突

- **场景**：用户绑定的热键与系统或其他软件冲突
- **系统行为**：后注册的热键覆盖先注册的（当前实现）→ 打印日志 → 无冲突提示弹窗
- **用户感知**：热键可能不生效或被其他软件拦截

### 7.3 Overlay 渲染失败

- **场景**：准星图片不存在、图片格式损坏、QPixmap 加载失败
- **系统行为**：打印 `[Overlay] 准星图片不存在: 路径` → Overlay 保持空白 → 不崩溃 → 下次切换时重试
- **用户感知**：准星不显示，控制台有错误日志

### 7.4 游戏全屏切换时 Overlay 行为

- **场景**：游戏在窗口化/全屏/无边框之间切换
- **系统行为**：Overlay 保持置顶（WindowStaysOnTopHint）→ 全屏游戏时 Overlay 仍可见 → 切换分辨率时 Overlay 自动适配主屏幕尺寸
- **用户感知**：Overlay 始终可见，无需手动调整

### 7.5 多显示器插拔

- **场景**：使用中插拔显示器或更改主显示器
- **系统行为**：Overlay 初始化时绑定主屏幕几何 → 运行中不动态响应显示器变化 → 程序重启后重新适配
- **用户感知**：插拔显示器后 Overlay 可能位置不对，重启程序恢复

### 7.6 资源文件缺失

- **场景**：配置中绑定的准星图片被用户手动删除
- **系统行为**：ResourceManager.get_resource_path() 返回 None → Overlay 打印日志并保持空白 → 资源库页不显示该文件 → 载具配置页绑定时显示未绑定
- **用户感知**：准星不显示，需重新绑定
